# Vibe Surgeon

**Показывает, куда смотреть после того, как ИИ изменил код.**

Локальный инструмент: карта импортов, оценка риска Git-изменений, замечания по
репозиторию, краткий контекст для следующей AI-сессии и HTML-отчёт.
API-ключ и регистрация не нужны. Это ранняя версия, а не гарантия качества.

## Проверить на примере

Нужны Git и Node.js 20+:

```bash
git clone https://github.com/adilusrr-gif/vibe-surgeon.git
cd vibe-surgeon
npm ci --ignore-scripts
npm run demo
```

Демо само создаст временный учебный репозиторий: изменится один файл, а проверка
покажет три потенциально затронутых файла. Отчёт и JSON с результатом сохранятся
в `.vibe-surgeon/demo/`. Исходники твоего приложения не меняются.

Это синтетический пример, не замер на клиентском проекте. Он показывает связи
файлов, но не доказывает, что изменение сломало бизнес-логику.

## Проверить свой проект

Из каталога Vibe Surgeon, подставив абсолютный путь:

```bash
node bin/vibe-surgeon.mjs all /путь/к/проекту
node bin/vibe-surgeon.mjs guard /путь/к/проекту --base HEAD
```

HTML: `/путь/к/проекту/.vibe-surgeon/report.html`.
`all` создаёт служебные файлы в `.vibe-surgeon/`; `scan` только выводит результат.
`guard --base HEAD` смотрит незакоммиченные изменения отслеживаемых файлов.
Для уже закоммиченных изменений укажи нужный предыдущий коммит. Новые
неотслеживаемые файлы в эту проверку не входят.

При ошибке Git проверка завершается с кодом 1, при высоком риске — с кодом 2.
Код 0 означает лишь, что эвристический порог не превышен, а не «код исправен».

## Ограничения

Тесты приложения не запускаются. 100/100 не означает отсутствие ошибок.
Граф импортов неполный: JS/TS-алиасы, динамические зависимости и Python требуют
доработки. Обнаружение `.env` не доказывает его наличие в Git. MCP не является
песочницей: подключай только доверенные локальные клиенты.

Пакеты распространяются через GitHub Releases. Публикация в npm здесь не
заявлена; не используй `npx vibe-surgeon@latest` без отдельной проверки.
